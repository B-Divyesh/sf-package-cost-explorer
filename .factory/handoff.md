# Package Cost Explorer — repair handoff

## Outcome: PASS

The production badge failure recorded in verifier-3 has been repaired and
deployed to the existing **Standard Azure Static Web App**. Production is
<https://package-cost-explorer.sociobot.in>.

The exact URL generated by a live report now succeeds:

```text
https://package-cost-explorer.sociobot.in/badge.svg?package=nanoid&version=5.1.5&gzip=473
HTTP 200
content-type: image/svg+xml
```

It returns a checked-in, inert SVG with `role="img"`; malicious query values
cannot create script or event-handler markup. This avoids the previous
unattached `/badge.svg` → `/api/badge` Azure Functions rewrite entirely.

## What changed

- Replaced the fragile Function-backed badge route with `public/badge.svg`, a
  static SVG served directly by Standard Azure Static Web Apps. The SWA
  configuration keeps `/badge.svg` outside the navigation fallback and assigns
  its short cache policy; there is no API folder or Function deployment.
- Kept the generated report URL meaningful (`package`, `version`, and `gzip`
  remain encoded in its query). “Copy measured badge” now produces a
  self-contained, escaped SVG data URL that visibly retains those exact
  measured values when embedded elsewhere.
- Added unit coverage for the canonical route, SVG value rendering, escaping,
  and data-URL embed. The real-report Playwright flow extracts the UI-generated
  live-route URL and asserts HTTP 200, `image/svg+xml`, an accessible SVG, and
  no script/event-handler content. `test:live` repeats those assertions
  against production from a clean browser profile.
- Browser analysis, export completeness, privacy behavior, PWA update handling,
  and the editorial visual system were left intact.

```sh
  --env production --swa-config-location dist --no-use-keychain
```

## Known limits

- A static host cannot interpolate untrusted URL query text into an SVG
  response. The live route is therefore an always-safe compatibility badge;
  the copied self-contained SVG is the visual embed that preserves the exact
  package/version/gzip measurement.
- Measurements remain browser/esbuild estimates. Peer dependencies, Node
  built-ins, CSS, static assets, native modules, and application-specific
  shared dependencies are disclosed rather than silently included.
