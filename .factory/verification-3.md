# Independent verification 3 — FAIL

**Verified 2026-08-27** from a clean checkout at candidate commit
`2f6622bf946a3cb948a5454430b6d83f5c143438` against
<https://package-cost-explorer.sociobot.in>.

## Verdict

**FAIL.** The static application deployed at the production URL matches the
candidate frontend and its core exports-aware analysis works end to end.
However, the required embeddable SVG badge is broken in production. The exact
badge URL generated by a successful live report returns **HTTP 500** with the
body `Backend call failure`, rather than an SVG. This is a stated v1 feature,
so the candidate cannot be accepted while its deployed worker route is down.

## Defect

### P1 — Production SVG badge worker returns 500

The completed live report generates:

`https://package-cost-explorer.sociobot.in/badge.svg?package=nanoid&version=5.1.5&gzip=473`

On 2026-08-27 it returned:

```text
HTTP/2 500

Backend call failure
```

There is no `content-type: image/svg+xml` response body. This was reproduced
by `npm run test:live` and direct HTTP inspection. The repository's badge unit
tests do pass locally, so deploy/enable and diagnose the Azure attached API
route (`/badge.svg` → `/api/badge`) rather than changing the client UI. Re-run
the exact UI-generated badge URL after repair.

## Acceptance condition

Re-verify once the exact live badge URL returns HTTP 200 with
`content-type: image/svg+xml` and safe SVG content. All other tested candidate
quality gates passed in this run.
